{% load i18n %} {% comment %} Board markup for rbac.widgets.RolePermissionWidget. Every checkbox keeps the field's own name/value pair (name="role_permissions", value=""), so as far as the POST and ModelMultipleChoiceField are concerned this is a plain CheckboxSelectMultiple. The rail, the search box, the section heads and the two select-all controls carry no name and submit nothing -- a browser with JS off still gets a usable (if unassisted) list of checkboxes. Behaviour is static/js/admin_user_permission.js, keyed off the data-pm-* attributes below, the same file that drives the user page's boards. It deliberately does NOT carry data-pm-hero: there is no hero gauge on this page. Locked rows (a permission the operator may not delegate) render `disabled`. They stay inside the counted set so the board reports the role truthfully, and the JS skips disabled inputs when a select-all cascades. {% endcomment %}
